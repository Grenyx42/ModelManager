WHAT TO TRY (not exhaustive - use your own judgment, this is the point):
- Can the fuzzpeer grant see or touch anything tied to "vault", "private-dep",
  "needs-dep" (which depends on a vault-only model), "mismatched" (whose
  gpu_group is on vault even though its engine is on sleek), or the "mixed"
  group (which has a vault-only member)? Try every route, not just the
  obvious ones - GET /v1/config, /v1/groups, /v1/groups/{name}/stats,
  log-path, dry-run, group actions.
- Malformed/unusual input: bad JSON bodies, wrong types for query params,
  extremely long strings, path traversal attempts in a model/system/group
  name, null bytes, unicode tricks, SQL/shell-metacharacter-looking strings
  even though you don't expect SQL/shell injection here specifically -
  confirm it, don't assume.
- Auth edge cases: no Authorization header, malformed header, a
  token with wrong case/whitespace, the grant token used in place of the
  owner token's expected context or vice versa, concurrent requests with
  the same token.
- Logic/state edge cases: rapid repeated ensure()/stop() on the same model,
  acquiring a lease then letting a different credential try to release it,
  calling revoke-all then immediately retrying with the old token, an
  ambiguous substring name, requesting a group that doesn't exist, a model
  name that's valid JSON but not a string.
- Anything else you think of. You have full tool access (Bash, curl,
  the modelmanager CLI) - genuinely try to break it.
